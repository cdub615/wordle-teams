Tokens, type, and components lifted from the live Next.js app — shadcn/ui on Tailwind with CSS-variable theming, a neutral base, and a green-to-yellow Wordle accent. Every value below is the value in production today; where the app has drifted from itself, it is flagged rather than silently fixed.

Drift & v2 notes

Places where today's code disagrees with itself. Documented as-is above; here is what to decide before rebuilding.

{{ d.title }} {{ d.body }}
Carry forward, unchanged The neutral-plus-one-accent discipline, the CSS-variable theme contract, the green/yellow game semantics, the pinned-column leaderboard, and the dialog-on-desktop / sheet-on-mobile split. Those are the system's real identity — everything else above is implementation.

Proposed for v2

A three-layer set that keeps the shadcn contract intact — --background, --primary, --muted and friends stay, so components need no edits — and adds the two things today's set is missing: real surface steps, and names for the accent instead of inline green-600. Values are hex here for legibility; ship them as HSL triplets exactly as today.

Layer 1 · Primitives Raw ramps, never used in a component Tailwind neutral plus a five-stop brand ramp. The only place a hex literal is allowed to live.
Layer 2 · Semantics What a color means Surfaces, text ranks, borders, status, and game state. Every pair ships its own foreground so contrast can't drift.
Layer 3 · shadcn aliases Compatibility shims The existing token names, redefined to point at layer 2. Nothing in ui/* changes on day one.

Three rules that keep it from drifting again
1 · No Tailwind color utility in a component. If green-600 appears outside the token file, it's a missing token. 2 · Background and foreground travel together. Never set one without the other from the same pair. 3 · One accent per surface. Green earns attention; yellow means "close"; nothing else gets to be saturated.
